# 노션 기능명세서 ↔ 실제 구현 대조 (API-Rate-Limiter)

> 노션: "여름 방학 프로젝트 – AI API 사용 제한 프로그램"
> 대상 폴더: `C:\Users\User\Desktop\API-Rate-Limiter`

| # | 명세 기능 | 우선순위 | 구현 상태 | 대응 코드 | 비고 |
|---|-----------|:---:|:---:|-----------|------|
| 1 | 요청 수 제한 | High | ✅ 완료 | `app/limiter.py`(Token Bucket), `app/api.py`(`/v1/check`) | 허용여부·잔여량·리셋시간 모두 출력 |
| 2 | 클라이언트 식별 | High | ✅ 완료 | `app/identify.py` | X-API-Key 우선 → IP 폴백 → client_id 정규화 |
| 3 | 제한 초과 처리 | High | ✅ 완료 | `main.py`(예외 핸들러) | 429 + Retry-After + 에러코드/메시지/retry_after |
| 4 | 사용량 조회 | - | ✅ 완료 | `app/api.py`(`/v1/usage`), `limiter.peek()` | 토큰 소비 없는 peek(cost=0) 구현 |
| 5 | 정책 설정 관리 | Medium | 🟡 부분 | `app/policies.py`, `PUT /v1/policies` | 동적 변경(재배포 불필요)은 됨. 단, **인메모리 저장**만 — Redis/설정파일 영속화는 미구현 |
| 6 | 모니터링·로깅 | Low | 🟡 부분 | `app/notifier.py` | 초과 시 알림(Slack/Discord/Telegram, 쿨다운)은 됨. **총요청·차단율 등 지표 수집/조회는 미구현** |

## 요약
- **High 우선순위 3개(요청 제한·클라이언트 식별·초과 처리) + 사용량 조회 = 100% 완료.**
- 부분 구현 2개:
  - **정책 관리**: 동적 변경 O / 영속 저장소(Redis·DB) X → 서버 재시작 시 정책 초기화.
  - **모니터링**: 알림 O / 통계 지표(metrics) 수집·노출 X.
- 추가 완성도 요소: Redis↔인메모리 자동 폴백, fail-open/close 정책, 한국어 Swagger 문서, pytest 테스트 4종.

**전체 진척도(가중 추정): 약 85%** (핵심 기능 완성, 영속화·지표 부분만 미완).
